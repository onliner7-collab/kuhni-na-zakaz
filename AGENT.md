# Обязательный вход в инженерный проект kuhni.minsk.by

1. Прочитать `docs/00_MASTER_PLAN.md`.
2. Прочитать документы текущего этапа и `docs/15_HANDOFF.md`.
3. Проверить `git status`, последние коммиты и фактический код.
4. Не считать этап выполненным только по документации.
5. Не менять URL, не удалять страницы и не копировать страницы с заменой города.
6. Не придумывать цены, адреса, проекты, филиалы, отзывы, характеристики или гарантии.
7. Не выдавать AI-контент за реальные проекты; видимые тексты и alt — на русском языке.
8. Использовать Server Components по умолчанию; Client Components изолировать и ограничивать.
9. Проектировать и проверять сначала 360–412 px: одна основная задача на экран, touch target не меньше 44×44 px, safe-area, Dock без перекрытий, без горизонтального scroll, с reduced motion.
10. Производительность и меньший клиентский JavaScript важнее декоративной анимации.
11. Перед изменением shared-компонента найти все его использования.
12. После каждого изменения обновлять Page, Component и Media Registry, Decision Log и Handoff.
13. В конце этапа выполнить доступные проверки, записать rollback и не начинать следующий этап до приёмки текущего.

Если документация противоречит фактическому коду, источником истины считается проверенный код. Расхождение необходимо зафиксировать в Decision Log и Handoff.
