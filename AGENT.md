# Постоянные правила проекта kuhni.minsk.by

Перед любой работой прочитать `AGENTS.md` и все документы `docs/00_PROJECT_VISION.md` — `docs/07_DECISION_LOG.md`.

- Не менять существующие URL и не удалять страницы без отдельного разрешения.
- Не менять canonical, metadata, `app/sitemap.ts`, `app/robots.ts`, редиректы и правила индексации без анализа и проверок.
- Проектировать mobile-first; производительность и понятность важнее декоративных эффектов.
- Использовать Server Components по умолчанию. Добавлять `"use client"` только изолированным интерактивным блокам.
- Не создавать новую страницу копированием другой: у страницы должны быть собственный вопрос, сценарий и интерактив.
- Не создавать массовые страницы вида «тип кухни × город» и не допускать каннибализации интентов.
- Все новые компоненты, данные и публичные интерфейсы типизировать.
- Перед изменением shared-компонента найти все места его использования.
- Внедрять изменения небольшими этапами; после каждого этапа выполнять доступные typecheck, lint, tests, build и мобильную проверку.
- Не выдавать AI-визуализации за выполненные проекты. Отмечать их как «AI-концепт» или «Иллюстрация процесса».
- Не придумывать цены, адреса, характеристики, гарантии, сроки и технические параметры.
- Новые кухонные изображения генерировать только встроенным Codex/OpenAI `imagegen`; существующие или стоковые изображения не подменяют требуемый новый ассет.
- Мастер нового изображения хранить в проекте; на сайт подключать оптимизированные AVIF/WebP, все alt и подписи писать по-русски.
- Значимые решения после работы фиксировать в `docs/07_DECISION_LOG.md`.

Рабочее приложение находится в `artifacts/kuhni-na-zakaz`. Production-код не переписывать массово; расширять существующие маршруты и компоненты совместимо.
