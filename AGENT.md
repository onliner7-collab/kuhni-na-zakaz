# Обязательный вход в инженерный проект kuhni.minsk.by

1. Прочитать `docs/00_MASTER_PLAN.md`.
2. Прочитать документы текущего этапа и `docs/15_HANDOFF.md`.
3. Проверить `git status`, последние коммиты и фактический код.
4. Не считать этап выполненным только по документации.
5. Не менять URL, не удалять страницы и не копировать страницы с заменой города.
6. Не придумывать цены, адреса, проекты, филиалы, отзывы, характеристики или гарантии.
7. Не выдавать AI-контент за реальные проекты; видимые тексты и alt — на русском языке.
8. Использовать Server Components по умолчанию; Client Components изолировать и ограничивать.
9. Проектировать и проверять сначала 360–412 px: одна основная задача на экран, touch target не меньше 44×44 px, safe-area, Dock без перекрытий, без горизонтального scroll, с reduced motion.
10. Производительность и меньший клиентский JavaScript важнее декоративной анимации.
11. Перед изменением shared-компонента найти все его использования.
12. После каждого изменения обновлять Page, Component и Media Registry, Decision Log и Handoff.
13. В конце этапа выполнить доступные проверки, записать rollback и не начинать следующий этап до приёмки текущего.

## Утверждённая Product Architecture этапа 4.5

14. Перед изменением публичной навигации прочитать все `docs/product/*.md`; это целевой продуктовый contract поверх существующих URL.
15. Пользовательская модель: «Выбрать кухню» объединяет форму, стиль, назначение, материалы и механизмы; `/catalog` показывается как «Идеи кухонь», `/portfolio` — как «Наши работы» только для подтверждённых реальных объектов.
16. Всё без подтверждённого происхождения считать идеей/визуализацией. Путь файла, запись в БД и город в названии не являются доказательством реального проекта.
17. Целевой global mobile Dock имеет постоянный порядок: `Выбрать / Цены / Наши работы / Оставить заявку`. Контекстные действия страницы не заменяют глобальные пункты и не создают второй fixed Dock.
18. Dock обязателен на всех публичных пользовательских страницах, включая `/calculator` и legal. Исключения: `/admin`, `/kapi`, `/robots.txt`, `/sitemap.xml`, `/thanks`, API/route handlers и непользовательские технические поверхности.
19. Плавающий баннер связи сохранять в текущем виде и поведении до отдельного решения.
20. Перед внедрением страницы выполнить diff-аудит каждого блока: `KEEP / ADAPT / REPLACE / MOVE / REMOVE`; работающий блок не переписывать без доказанного UX, SEO или performance риска.

## Product этап 5

21. Глобальный Dock использует существующий `MobileBottomNav`; порядок: «Выбрать / Цены / Наши работы / Оставить заявку».
22. Короткая заявка Dock требует имя, телефон и согласие, передаёт контекст страницы и использует действующую Lead/Telegram систему.

Если документация противоречит фактическому коду, источником истины считается проверенный код. Расхождение необходимо зафиксировать в Decision Log и Handoff.
