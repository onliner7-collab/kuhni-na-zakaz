Ты продолжаешь production-ready коммерческий SEO-сайт по продаже кухонь на заказ.

Работай только на основе текущего кода репозитория и project-docs. Ничего не выдумывай. Сначала анализируй существующую реализацию, потом меняй код.

Ключевые правила проекта:
- Next.js App Router
- TypeScript
- Tailwind CSS
- Prisma + PostgreSQL
- people-first
- mobile-first
- SEO-first для индексируемых страниц
- SSR/SSG architecture
- контент должен управляться через БД/админку, а не через хардкод
- нельзя делать одинаковые городские страницы-клоны
- нельзя игнорировать project-docs
- нельзя менять архитектуру без обновления project-docs/CHANGELOG.md и project-docs/HANDOFF.md

Брендовая логика:
- главная страница должна позиционировать бренд по всей Беларуси
- нельзя позиционировать бренд на главной как только минский
- Минск и Минская область допустимы только на локальных страницах и в локальном SEO

Админ-панель:
- всё, что редактируется менеджером или владельцем, должно по возможности идти через админку и БД
- если для новой публичной фичи не хватает сущностей, полей, API, форм или экранов в админке, добавь это
- не оставляй новую контентную логику захардкоженной в .ts/.tsx как основной источник истины
- все admin-функции должны быть понятны обычному человеку и иметь русские подписи
- новые сущности/поля должны быть синхронизированы между Prisma, admin UI, admin API и публичным сайтом

Безопасность:
- не использовать fallback secret для SESSION_SECRET
- не ослаблять auth
- не открывать /admin публично
- роли и ограничения не ломать

SEO:
- сохраняй или улучшай unique title, unique description, H1, canonical, robots, sitemap, JSON-LD
- не делать thin content
- не делать fake SEO pages
- pages styles/materials/locations должны оставаться полноценными посадочными

Формат работы:
1. Сначала кратко опиши, что уже есть в коде по этой задаче.
2. Затем перечисли, что нужно изменить.
3. Затем внеси изменения в код.
4. Обязательно обнови project-docs/CHANGELOG.md и project-docs/HANDOFF.md.
5. В конце покажи:
   - что сделано
   - какие файлы изменены
   - какие Prisma-модели/поля добавлены
   - какие admin pages/API/forms добавлены или изменены
   - какие публичные страницы изменены
   - какие риски остались
Не делай предположений, если можно посмотреть код.
