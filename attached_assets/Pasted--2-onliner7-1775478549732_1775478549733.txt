Этап 2 — Бренд и позиционирование главной: Беларусь, а не Минск

Работаем в репозитории:
onliner7-collab/kuhni-na-zakaz

Ветка:
work

Нужные скиллы для этого этапа:
- Next.js App Router
- SEO для Next.js
- Metadata API (`title`, `description`, Open Graph, Twitter)
- JSON-LD / Schema.org
- React / TSX
- аккуратный рефакторинг контентных и metadata-строк без поломки архитектуры
- понимание различия между:
  - глобальным брендовым позиционированием
  - локальными SEO-страницами по городам
- git hygiene: точечные изменения, без мусора и без затрагивания несвязанных файлов
- documentation hygiene: changelog/handoff только по факту, без неподтверждаемых заявлений

Задача этапа:
убрать с главной страницы и из общебрендовых зон сайта минское позиционирование и привести проект к корректному бренду:
не “кухни в Минске”, а “кухни по Беларуси” / “кухни на заказ по Беларуси”.

Что нужно сделать:
1. Проверить и исправить все общебрендовые места, где проект позиционируется как минский, если это не локальная SEO-страница:
   - `app/page.tsx`
   - `app/layout.tsx`
   - header
   - footer
   - homepage metadata
   - homepage JSON-LD / schema
   - SiteSettings defaults
   - глобальные title/description/OpenGraph/Twitter metadata
   - тексты hero / CTA / trust / guarantees / about snippets на главной
   - canonical, если там зашито минское позиционирование
   - любые глобальные fallback-строки бренда

2. Главная должна быть позиционирована как:
   - “Кухни на заказ по Беларуси”
   - “Изготавливаем кухни по индивидуальным размерам по Беларуси”
   - “Работаем по всей Беларуси”
   Формулировки можно улучшить, но смысл должен остаться именно общереспубликанским.

3. Минск НЕ удалять из локальных и региональных страниц, где он уместен:
   - `/locations/*`
   - локальные SEO-посадочные
   - контент, относящийся именно к конкретному городу
   - кейсы, отзывы, адреса, где Минск — это фактические данные

4. Если в schema.org / JSON-LD на главной зашит LocalBusiness с Минском как единственной зоной покрытия —
   исправить так, чтобы главная отражала работу по Беларуси.
   Нельзя оставлять противоречие: в тексте “по Беларуси”, а в structured data только “Минск”.

5. Проверить и исправить:
   - `title`
   - `description`
   - `H1`
   - Open Graph title/description
   - Twitter metadata
   - JSON-LD name/description/areaServed
   - brand text в header/footer
   - глобальные дефолты контактов/описаний, если там жёстко зашит Минск как позиционирование всего бренда

6. Ничего не ломать по архитектуре:
   - не трогать рабочую auth-логику
   - не возвращать `.next/` в git
   - не создавать лишних рефакторингов вне задачи
   - не менять локальные страницы без необходимости

Что запрещено:
- Нельзя оставлять на главной или в глобальном бренде фразы типа:
  - “кухни на заказ в Минске”
  - “изготовление кухонь в Минске”
  - “лучшие кухни Минска”
  если речь идёт не о локальной отдельной странице.
- Нельзя писать в changelog или handoff неподтверждаемые вещи вроде “полностью готово к production”, если это не проверено.
- Нельзя делать косметические массовые изменения вне этой задачи.

Критерий готовности этапа:
Этап считается завершённым только если:
1. Главная страница и глобальные брендовые зоны больше не позиционируют проект как только Минск.
2. Главная и metadata отражают Беларусь / работу по Беларуси.
3. Structured data на главной не противоречит новому позиционированию.
4. Локальные минские / городские страницы сохранены и не сломаны.
5. Изменения точечные, чистые и логически ограничены Этапом 2.

Что сдать по завершению:
1. Список изменённых файлов.
2. Кратко — что именно было исправлено в каждом.
3. SHA финального коммита.
4. Отдельно перечислить:
   - новый homepage title
   - новый homepage description
   - новый H1
   - что поменялось в JSON-LD / schema
5. Обновить `project-docs/CHANGELOG.md` и `project-docs/HANDOFF.md` только фактами, без догадок.

Формат работы:
- Сначала внести изменения.
- Потом сделать один аккуратный git commit.
- В ответе дать только фактический отчёт по сделанному и SHA коммита.
