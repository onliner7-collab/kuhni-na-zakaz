Да, это нужно переделать.

По твоему описанию админка сейчас в плохом состоянии по трём направлениям:

* доступ открыт слишком широко;
* интерфейс не подходит для обычного человека;
* язык и структура не помогают понять, что именно редактируется.

Я не могу подтвердить конкретные файлы и уже внесённые изменения, потому что в этой сессии у меня нет надёжного доступа к актуальному коду админки. Но по задаче могу точно сказать, что должно быть сделано.

Что нужно изменить в админке

**1. Закрыть админку по логину и паролю**
Нужно, чтобы:

* `/admin/login` был единственной публичной страницей админки;
* все остальные `/admin/*` открывались только после авторизации;
* вход был по email или логину и паролю;
* пароль хранился только в хешированном виде;
* сессия проверялась на сервере, а не только на клиенте;
* был logout;
* без `SESSION_SECRET` приложение вообще не запускало auth-часть.

Минимум:

* middleware на `/admin/:path*`
* server-side guard внутри каждой admin page
* server-side guard в каждом admin API route

**2. Перевести всю админку на русский**
Нужно убрать английские названия разделов и действий.

Примеры замены:

* Dashboard → **Панель управления**
* Kitchens → **Кухни**
* Portfolio → **Портфолио**
* Reviews → **Отзывы**
* Blog → **Блог**
* Locations → **Страницы городов**
* Settings → **Настройки сайта**
* Users → **Пользователи**
* Guest Access → **Гостевой доступ**
* Activity Log → **Журнал действий**
* New → **Добавить**
* Edit → **Редактировать**
* Delete → **Удалить**
* Published / Draft → **Опубликовано / Черновик**
* Save → **Сохранить**
* Cancel → **Отмена**

**3. Сделать интерфейс понятным обычному человеку**
Сейчас, по твоему описанию, админка сделана “как для разработчика”, а нужна “как для менеджера”.

Что должно быть:

* понятное левое меню;
* крупные русские заголовки;
* короткие пояснения под каждым разделом;
* карточки с понятным смыслом;
* формы с подписями “что это влияет на сайте”;
* предпросмотр или ссылка “открыть на сайте”;
* отдельные кнопки “Добавить”, “Редактировать”, “Скрыть”, “Опубликовать”;
* статусы с цветом и русским текстом;
* подтверждение перед удалением;
* success/error сообщения на русском.

Пример структуры меню:

* **Панель управления**
* **Кухни**
* **Цены**
* **Портфолио**
* **Отзывы**
* **Страницы сайта**
* **Блог**
* **Города и регионы**
* **Настройки сайта**
* **Пользователи**
* **Гостевой доступ**
* **Журнал действий**

**4. Сделать понятные карточки и формы**
У каждой сущности должно быть ясно:

* что это за запись;
* где она показывается;
* опубликована она или нет;
* можно ли открыть её на сайте;
* когда обновлялась;
* кто редактировал.

Например карточка кухни:

* Название кухни
* Slug
* Статус: Черновик / Опубликовано
* Краткое описание
* Цена “от”
* Дата обновления
* Кнопки: **Редактировать**, **Открыть на сайте**, **Снять с публикации**, **Удалить**

У формы должны быть пояснения:

* **Название кухни** — отображается в карточке и в заголовке страницы
* **SEO title** — заголовок для Google и Яндекс
* **SEO description** — описание в поиске
* **Основное фото** — главное изображение карточки
* **Краткое описание** — показывается в списках и превью
* **Полное описание** — текст на странице кухни

**5. Разделить контент по смыслу**
Обычному человеку должно быть понятно, куда идти.

Логика разделов:

* **Кухни** — каталог кухонь
* **Портфолио** — реальные выполненные проекты
* **Отзывы** — отзывы клиентов, только после модерации
* **Блог** — статьи
* **Города и регионы** — локальные SEO-страницы
* **Настройки сайта** — телефон, адрес, бренд, соцсети, метаданные, реквизиты
* **Страницы сайта** — about, warranty, delivery, contacts и т.д.

**6. Ограничить права**
Даже если вход по логину/паролю появится, этого недостаточно.

Нужно:

* **Super Admin** — полный доступ
* **Manager** — контент без управления пользователями и системными настройками
* **Guest Admin** — только временный и только к разрешённым разделам
* все права проверять на сервере

**7. Убрать “непонятность” в UX**
Нужны элементы, которые помогают не ошибиться:

* хлебные крошки;
* “Вы редактируете: Кухня → Модерн Белый”;
* “Эта запись отображается на странице /catalog/[slug]”;
* “Изменения не опубликованы”;
* “Эта запись сейчас скрыта на сайте”;
* автосохранение черновика или хотя бы предупреждение при уходе со страницы.
