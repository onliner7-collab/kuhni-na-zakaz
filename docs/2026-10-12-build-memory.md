# Память сборки — 12 октября 2026

VPS: 2 ГБ RAM, 2 CPU, постоянный swap 2 ГБ. Ядро подтвердило global OOM во время сборки Next.js 15.3.9. Дополнительные 4 ГБ временного swap также были исчерпаны. Сайт восстанавливался автоматически; для диагностики третья сборка остановлена адресно по PID её webpack worker.

Обнаружено много каталогов резервных и неудачных сборок `.next-before-*`, `.next-budget-*`, `.next-straight-*` рядом с приложением. Каждый крупный каталог занимает около 350–422 МБ. Старый `.gitignore` исключал только `.next/` и `.next-seo-ownership/`. Tailwind v4 использует автоматическое обнаружение исходников и учитывает `.gitignore`; артефакты сборок должны быть исключены.

Постоянная правка: `artifacts/kuhni-na-zakaz/.gitignore` получает `.next*/`. Это исключает все сборки и резервные копии из Git и автоматического обхода Tailwind, не удаляя их и не меняя исходные компоненты. Эффект проверяется чистой production-сборкой и браузерной регрессией. Потребление памяти Rust/Tailwind и других нативных частей не ограничивается только лимитом V8 heap.

Временный профиль деплоя: один worker, webpackMemoryOptimizations, явный webpackBuildWorker, cache=false, parallelism=1, RAYON_NUM_THREADS=1 и UV_THREADPOOL_SIZE=2. Настройки Next.js после сборки восстанавливаются; swap создаётся только на время деплоя и удаляется cleanup.

Для долговременного процесса публикаций рекомендуется Linux CI с передачей готовой сборки. Если собирать на VPS, объём RAM следует выбирать по измеренному пику. Увеличение тарифа не выполнено; CI не подключён и секреты в GitHub не передавались.

Источник поведения сканера: [Tailwind — обнаружение классов](https://tailwindcss.com/docs/detecting-classes-in-source-files). Настройки памяти: [Next.js — memory usage](https://nextjs.org/docs/app/guides/memory-usage).
