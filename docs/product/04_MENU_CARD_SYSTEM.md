# Система карточного меню

## Назначение

Карточное меню переводит длинные списки маршрутов в выбор по задаче пользователя. Оно не создаёт новые URL и не скрывает ссылки от поисковых систем.

## Карточка

Обязательные элементы:

- смысловое изображение или лёгкая иллюстрация;
- короткий русский заголовок;
- одна строка объяснения;
- понятное направление перехода;
- вся карточка — обычная `<a href>`;
- кликабельная зона минимум 44×44 px;
- visible focus и достаточный контраст.

Запрещены технические названия, внутренние ID и одинаковые декоративные изображения без смысловой разницы.

## Основные семейства

### Форма кухни

- Прямая — «Для одной стены и компактного пространства».
- Угловая — «Использует две стены и добавляет рабочую поверхность».
- П-образная — «Даёт много хранения при достаточных проходах».
- С островом — «Для просторного помещения после проверки расстояний».
- Маленькая — «Помогает вместить основные функции без перегруза».
- До потолка — «Использует высоту для дополнительного хранения».
- Без ручек — «Показывает способы открывания и ограничения».

### Стиль

Карточки показывают характер внешнего вида, а не только цвет: современный, минимализм, неоклассика, классика, скандинавский, лофт, прованс, хай-тек.

### Назначение

Карточки отвечают на бытовую задачу: квартира, дом, студия, семья, маленькое помещение, хранение до потолка, ограниченный бюджет. Точный набор определяется существующими `/scenarios/*`.

### Материалы и механизмы

Карточки объясняют, что пользователь узнает: фасады, столешницы, корпуса, петли, направляющие, подъёмные механизмы, карго и угловое хранение.

## Responsive contract

- 360–412 px: одна крупная карточка или явный horizontal snap; виден край следующей карточки и подсказка «Листайте».
- Swipe не единственный способ: доступны кнопки/ссылки и keyboard scroll.
- 768 px: две-три колонки по смысловой группе.
- 1440 px: сетка или mega-menu без изменения порядка и IA.
- Не загружать все изображения меню до открытия; critical media — только фактически видимый initial item.
- `prefers-reduced-motion` убирает декоративные перемещения, но не скрывает карточки.

## Состояния

| Состояние | Поведение |
| --- | --- |
| Default | Изображение, заголовок, объяснение и ссылка доступны |
| Hover | Небольшая подсветка без перемещения layout |
| Focus | Явное focus ring, контент не обрезан |
| Active | Маркируется текущая группа, не блокирует ссылку |
| Missing media | Текстовая карточка с устойчивым фоном/иконкой |
| Loading | Зарезервирован aspect ratio, без CLS |
| Error | Текст и ссылка остаются рабочими |

## Контентные правила

- «Каталог» в пользовательском меню заменяется на «Идеи кухонь», но URL `/catalog` сохраняется.
- «Портфолио» заменяется на «Наши работы» только для подтверждённых объектов.
- Нельзя писать «SEO-раздел», «SEO-фото», «asset», «component», «stage» и другие служебные термины.
- Название карточки описывает решение, а не структуру папок.

## Технический contract будущей реализации

`MenuCard` остаётся Server Component по умолчанию. Client boundary нужен только для раскрытия панели, состояния active и управления focus. Ссылки и основные подписи присутствуют в HTML до hydration.
