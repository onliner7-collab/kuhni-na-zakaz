# Спецификация глобального Dock

Статус: целевой контракт этапа 5. Текущий `MobileBottomNav` не изменяется на этапе 4.5.

## Постоянный состав

Порядок одинаков на всех публичных пользовательских страницах:

| Позиция | Подпись | Назначение | Active mapping |
| ---: | --- | --- | --- |
| 1 | Выбрать | `/catalog` и вход в выбор кухни | `/catalog*`, `/styles*`, `/scenarios*`, `/materials*` |
| 2 | Цены | `/prices` | `/prices`, `/calculator` |
| 3 | Наши работы | `/portfolio` | `/portfolio*` только в роли подтверждённых проектов |
| 4 | Оставить заявку | открыть `LeadFormSheet` | не получает `aria-current`; визуально primary |

Каждый пункт имеет иконку и текст. Подпись «Оставить заявку» не сокращается до одной иконки или неоднозначного «+».

## Coverage

Dock выводится на всех публичных пользовательских страницах, включая `/calculator` и юридические страницы.

Исключения:

```text
/admin
/kapi
/robots.txt
/sitemap.xml
/thanks
```

Также исключаются API, route handlers, файлы и служебные поверхности без пользовательского интерфейса.

## Поведение заявки

1. Tap/click открывает короткий `LeadFormSheet` максимум за одно действие.
2. Заголовок и неперсональный контекст зависят от страницы, но структура первого шага одинакова.
3. Поля первого шага: имя, телефон или способ связи, submit.
4. Дополнительные поля раскрываются по желанию и не блокируют сохранение контакта.
5. Focus переходит в заголовок/первое поле, удерживается внутри sheet и возвращается на trigger.
6. Escape и явная кнопка закрытия работают.
7. При отправке используется действующая `/kapi/leads` и Telegram/outbox модель; Telegram failure не отменяет сохранённую заявку.

## Mobile layout

- Только mobile/tablet до согласованного breakpoint; desktop использует header CTA.
- Минимальный target 44×44 px, включая крайние пункты.
- Учитываются `env(safe-area-inset-bottom)` и реальная высота Dock.
- `main` получает измеренную нижнюю компенсацию.
- Двухстрочные подписи допустимы на 360 px, если не обрезаются и не уменьшают target.
- Dock скрывается при открытом dialog/sheet, экранной клавиатуре и focus внутри формы, если иначе перекрывает ввод или ошибки.
- Нельзя создавать второй fixed bottom navigation.

## Active state

- Одновременно активен не более одного навигационного пункта.
- Активность определяется ролью route, а не совпадением случайного substring.
- «Оставить заявку» выделяется как primary action, но не объявляется текущей страницей.
- На `/` допускается отсутствие `aria-current`; визуальный primary остаётся только у заявки.

## Контекстные действия страницы

Текущие наборы `Планировка / Внутри / Цена / Рассчитать`, `Виды / Процесс / Стоимость / Замер` и `Механизмы / Сравнить / Комплектация / Подобрать` полезны, но не являются глобальной навигацией.

В будущем они переносятся в `PageActionRail`:

- после hero или рядом с оглавлением;
- обычные якоря/ссылки;
- допускается горизонтальный scroll с явной подсказкой;
- не fixed снизу;
- не заменяет глобальный Dock и кнопку заявки.

## Плавающий баннер

`FloatingSocialButtons` сохраняется с текущим движением, размером и каналами до отдельного решения. При внедрении Dock проверяются z-index, overlap и состояние открытой панели. Dock не подменяет плавающую связь, а плавающая связь не подменяет заявку.

## Acceptance этапа 5

- 360/390/412/768/1440;
- одинаковые четыре подписи и порядок на всех public route groups;
- нет Dock на исключениях;
- active state корректен;
- форма открывается одним действием;
- focus/Escape/restore/safe-area/reduced motion работают;
- нет overlap с контентом, submit, ошибками, баннером и клавиатурой;
- обычные crawlable ссылки остаются в server HTML;
- production code меняется только после отдельного diff-аудита.
