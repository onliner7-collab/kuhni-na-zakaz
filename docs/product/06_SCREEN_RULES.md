# Правила экранов

## Базовый contract

Один экран отвечает на один главный вопрос. Экран — это смысловая зона мобильной страницы, а не произвольная высота компонента.

Формула:

```text
одна мысль → один ответ → одно главное действие
```

Следующий экран обязан добавлять новое знание или новый шаг решения. Повтор одинаковых галерей, преимуществ и CTA без новой ценности запрещён.

## Первый экран

Обязательно:

- один ясный H1;
- объяснение в 1–3 коротких строках;
- один основной CTA;
- максимум одно вторичное действие;
- один смысловой визуальный объект;
- подпись происхождения медиа;
- понятная подсказка, если есть свайп, сравнение или раскрытие.

H1, объяснение и основной CTA должны читаться на 360 px без zoom и без обязательной прокрутки. Hero не обязан занимать весь viewport.

## Типы экранов

| Тип | Главный вопрос | Допустимое действие |
| --- | --- | --- |
| Выбор | Какой вариант подходит? | выбрать/сравнить 2–7 вариантов |
| Объяснение | Почему это важно? | открыть пример или ограничение |
| Механизм | Как это работает? | переключить состояние, не autoplay |
| Доказательство | Что реально сделано? | открыть подтверждённый проект |
| Цена | Что меняет стоимость? | перейти к расчёту |
| Процесс | Что будет дальше? | раскрыть этап |
| Переход | Куда двигаться после ответа? | одна основная и до 3 вторичных ссылок |
| Конверсия | Как передать контакт? | короткая заявка |

## Состояния интерактива

Каждый интерактив описывает:

- default;
- user intent/active;
- loading;
- empty;
- media error;
- success/result;
- reduced motion;
- no-JS/static fallback.

Отсутствующее изображение не делает экран пустым. Текст и следующий шаг остаются доступными.

## Mobile

- 360, 390, 412 px — обязательная матрица.
- Touch targets минимум 44×44 px.
- Основной текст читается без zoom.
- Нет горизонтального page scroll.
- Horizontal scroller используется только с видимой подсказкой, snap и keyboard/button alternative.
- Fixed surfaces учитывают safe-area и не перекрывают submit/errors/последний control.
- Длинная форма не является первым действием.

## Tablet и desktop

- 768 и 1440 px сохраняют порядок и смысл mobile IA.
- Desktop может использовать split layout, rail или дополнительные колонки, но не получает отдельный сценарий.
- Дополнительная ширина не является причиной загружать больше медиа или включать autoplay.

## Motion

- Motion объясняет изменение состояния, но не заменяет его.
- Hover не является обязательным способом доступа.
- `prefers-reduced-motion` отключает перелёты, интерполяцию, autoplay и path drawing.
- После отключения motion все действия и ответы остаются доступны.

## Текстовая плотность

- Один абзац объясняет одну мысль.
- Длинный SEO-текст не становится интерфейсом; он структурируется по реальным вопросам.
- Профессиональный термин сопровождается понятным объяснением.
- Заголовок не повторяет предыдущий экран другими словами.

## Diff-аудит перед внедрением

Каждый существующий блок получает один статус:

| Статус | Значение |
| --- | --- |
| KEEP | Уже отвечает требованиям; сохранить |
| ADAPT | Сохранить смысл/данные, изменить подачу |
| REPLACE | Заменить доказанно неработающий UX |
| MOVE | Сохранить блок, изменить место в пути |
| REMOVE | Удалить только при доказанной избыточности |

Для каждого решения записываются доказательство, риск, затронутые связи и rollback.

## Приёмка экрана

- вопрос и ответ можно назвать одним предложением;
- primary CTA один;
- видимая ценность отличается от соседних экранов;
- доступность и fallback определены;
- media имеет функцию и provenance;
- важный смысл доступен в server HTML;
- следующий переход существует;
- экран не повторяет другой route с заменой заголовка или города.
