# Пользовательские пути

Статус: целевой контракт этапа 4.5; URL не меняются.

## Основной путь выбора

`Главная → Выбрать кухню → Форма → Стиль → Назначение → Материалы и механизмы → Наши работы → Цена → Оставить заявку`

### Состояния пути

| Шаг | Вопрос | Решение пользователя | Следующий шаг | Ошибка/пустое состояние |
| --- | --- | --- | --- | --- |
| Главная | Что здесь можно получить? | Начать выбор | Карточная навигация | Показать обычные ссылки без JS |
| Форма | Какая планировка поместится? | Прямая, угловая, П-образная, островная и др. | Стиль или категория | Если не знает — сценарий помещения |
| Стиль | Какой внешний вид подходит? | Выбрать визуальное направление | Назначение/материалы | Показать сравнение, не требовать выбора |
| Назначение | Как кухня будет использоваться? | Квартира, дом, студия, семья и др. | Материалы | Если сценария нет — общий расчёт |
| Материалы | Что выбрать для фасадов и столешницы? | Зафиксировать интерес | Механизмы | Текстовый fallback без медиа |
| Механизмы | Где удобство важнее экономии? | Выбрать уровень обсуждения | Идеи/работы | Результат — brief, не спецификация |
| Наши работы | Есть ли реальные доказательства? | Открыть подтверждённый проект | Цена | Честное empty state без визуализаций |
| Цена | От чего зависит смета? | Перейти к расчёту | Заявка | Не обещать точную цену без проекта |
| Заявка | Как быстро передать контакт? | Имя + связь + submit | Успех/Telegram | Ошибка сохраняет введённые данные |

## Путь от визуального интереса

`Увидел кухню → Открыл идею → Посмотрел устройство → Изучил материалы → Проверил реальные работы → Запросил расчёт`

- Идея всегда имеет маркировку происхождения.
- Изображение ведёт на существующую страницу формы, стиля, материала или механизма.
- Визуализация не ведёт себя как подтверждённый кейс.
- При отсутствии реального похожего проекта показывается честное сообщение и ссылка на общие «Наши работы».

## Путь из статьи

`Статья → Ответ на вопрос → Подходящая категория/материал → Подтверждённый проект или идея → Цена → Заявка`

- Статья сначала отвечает на информационный вопрос.
- Коммерческий переход контекстный, а не вставленный ради ключевой фразы.
- Не менее одного релевантного перехода должно быть доступно до финального CTA.

## Путь из локации

`Локация → Условия работы в городе → Форма кухни → Доставка/замер → Наши работы или идеи → Расчёт`

- Городская страница не придумывает филиал или локальный объект.
- Реальный проект показывается только при подтверждённой связи с городом.
- При отсутствии локального проекта выводится empty state и отдельно маркированные идеи.

## Путь из материала

`Материал → Фактура → Плюсы и ограничения → Сравнение → Подходящие кухни → Механизмы → Расчёт`

- Материал не обещает свойства без источника.
- Важные ограничения видны до CTA.
- Сравнение доступно текстом без обязательного интерактива.

## Путь из реального проекта

`Наши работы → Проект → Форма → Стиль → Материалы → Локация → Похожий проект → Рассчитать похожую кухню`

- Проект имеет подтверждённое происхождение.
- Если поле не подтверждено, оно не используется как доказательство.
- CTA передаёт неперсональный контекст проекта в форму, но отправка остаётся явной.

## Конверсионный путь с любой страницы

1. Пользователь нажимает «Оставить заявку» в Dock.
2. Открывается короткий `LeadFormSheet` с заголовком по контексту страницы.
3. Первый шаг содержит имя, телефон или способ связи и кнопку отправки.
4. Дополнительные поля раскрываются по желанию.
5. После успешного сохранения показывается понятный статус и необязательное продолжение в Telegram.
6. Ошибка Telegram не отменяет уже сохранённую заявку.

## Аналитические события будущего внедрения

Минимум: открытие меню, выбор карточки, переход между этапами выбора, открытие формы из Dock, успешная заявка, переход к подтверждённому проекту, переход от идеи к материалу/категории. Названия событий являются технической деталью и не выводятся пользователю.
