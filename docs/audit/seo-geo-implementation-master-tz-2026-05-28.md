## Правила использования skills и MCP

Skills можно использовать без ограничений, но по делу. MCP использовать осознанно: они дорогие по токенам, поэтому не открывать документацию и браузер "на всякий случай".

### Skills по этапам

- `technical-seo-developer`: обязательно для этапов с routes, metadata, sitemap, robots, llms.txt, canonical, schema, redirects.
- `geo-content-optimizer`: обязательно для текстов городских страниц, FAQ, GEO/AI citation readiness.
- `keyword-research`: использовать при разборе Excel, кластеров, посадочных и при выборе связок город + тип кухни.
- `image-generation-brief`: обязательно перед генерацией изображений.
- `imagegen`: использовать для генерации 3D/AI-визуализаций кухонь. Локальные папки с фото не использовать.
- `accessibility-performance-qa`: обязательно перед финальной сдачей этапа.
- `playwright`: обязательно для ручной проверки интерфейса, кликов, навигации, адаптива, визуальной приемки и проверки после деплоя.
- `technical-seo-checker`, `on-page-seo-auditor`, `content-quality-auditor`: использовать для финальной SEO-проверки страниц и контента.

### MCP/инструменты

- Browser/Playwright MCP: использовать для проверки локального сайта, production-сайта, Google Search Console, Яндекс Вебмастера, кликов, форм, навигации, адаптива.
- OpenAI/Context7 docs MCP: использовать только если нужно уточнить актуальное поведение API/библиотеки или Next.js-паттерн, который нельзя надежно понять из кода.
- Web search: использовать только если нужна актуальная внешняя информация, SERP, документация поисковиков, или проверка живого сайта/конкурентов.
- Image generation tool: использовать для 3-5 изображений на новую посадочную страницу, если этап создает страницы.

Не тратить MCP на:

- повторное чтение уже сохраненных отчетов, если они есть локально;
- общий "SEO совет";
- поиск того, что уже есть в Excel или проекте;
- массовое открытие документации без конкретного вопроса.

## Визуальная стратегия

Новые страницы не обязаны быть одинаковыми. Они должны быть уникальными, красивыми, живыми и удерживающими внимание. Допускаются:

- анимации;
- мягкие градиенты;
- выразительные hero-секции;
- разные композиции;
- разные цветовые акценты;
- интерактивные блоки;
- нестандартные, но удобные секции.

Но дизайн не должен ломать доверие и UX. Страница должна выглядеть как часть сайта КухниBY, а не как случайный лендинг.

## Правила изображений

Локальные папки `E:/фото кухни 3` и `E:/фото кухни2` для этой задачи не использовать. Все новые изображения генерировать.

Для каждой новой городской страницы нужно 3-5 изображений:

- 1 hero-изображение;
- 2-3 изображения проекта в разных ракурсах;
- 1 деталь: фасады, столешница, фурнитура, подсветка, зона хранения.

Все AI/3D изображения должны:

- быть сохранены в проекте, а не только во временной папке;
- быть оптимизированы в webp/avif, если проект это поддерживает.

Каждый промт на генерацию изображения должен писать человек с опытом интерьерной съемки:

- указать тип кухни: угловая, прямая, П-образная, до потолка, с островом, маленькая, студия;
- указать стиль: современный минимализм, сканди, неоклассика, japandi, loft, warm modern, premium family;
- указать материалы: матовый МДФ, ЛДСП под дерево, HPL, акрил, шпон, каменная/кварцевая столешница;
- указать свет: утренний мягкий свет, боковой оконный свет, теплый LED в нишах, реалистичные тени;

## Структура каждой новой городской страницы

Каждая страница должна быть уникальной. Не копировать один текст с заменой города.

Минимальная структура:

1. Hero:
   - H1: `Кухни на заказ в <городе>`
   - короткий оффер;
   - цена от;
   - срок производства;
   - доставка/замер;
   - CTA;
   - hero image с ватермаркой.

   - 25-50 слов, GEO-friendly.

   - особенности домов/квартир/дач в этом направлении;
   - как планируется замер;
   - почему логистика отличается.
4. Популярные решения:
   - угловая;
   - прямая;
   - до потолка;
   - маленькая;
   - для частного дома/студии, если уместно.
5. Галерея 3D-визуализаций:
   - 3-5 изображений;
   - подписи;
   - alt;
   - watermark.
6. Как проходит заказ:
   - заявка;
   - замер;
   - 3D-проект;
   - смета;
   - производство;
   - доставка;
   - монтаж.
7. Цены и что влияет:
   - материал фасадов;
   - метраж;
   - столешница;
   - фурнитура;
   - встроенная техника;
   - доставка.
8. Зона работ:
   - город;
   - район/ближайшие населенные пункты;
   - соседние посадочные.
9. FAQ:
   - 4-6 вопросов.
10. Внутренние ссылки:
   - `/locations/minskaya-oblast`;
   - соседние города;
   - 3-5 категорий каталога;
   - `/prices`, `/calculator`, `/portfolio`.
11. CTA внизу:
   - форма;
   - город и cityKey должны передаваться корректно.

## SEO-требования к каждой странице

- URL без кириллицы, без дублей.
- 200 status.
- Canonical на себя.
- Title 45-65 символов.
- Description 120-160 символов.
- Один H1.
- Логичная H2/H3 структура.
- Видимый FAQ совпадает с FAQPage JSON-LD.
- BreadcrumbList JSON-LD.
- Service/LocalBusiness/Place schema, если поддержано текущими helper-ами.
- OpenGraph title/description/image.
- Изображения с alt на русском.
- Страница есть в sitemap.
- Страница есть в `/locations` и `/locations/minskaya-oblast`.
- Есть ссылки назад на главную и хабы.
- Нет `noindex`.
- Нет битых ссылок.
- Нет фальшивого "реального фото", если изображение AI/3D.
