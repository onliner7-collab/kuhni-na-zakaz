# Техническое задание на внедрение SEO/E-E-A-T усиления сайта kuhni.minsk.by

Дата: 2026-06-04
Сайт: https://kuhni.minsk.by
Цель: усилить сайт для роста по запросам "кухни на заказ Минская область", городским запросам Минской области и коммерческим запросам по Минску за счет реальных доказательств, фото, портфолио, аналитики, локальных сигналов и технической SEO-доработки.

## 1. Главный принцип внедрения

На сайте нельзя выдавать AI/3D-изображения за реальные выполненные проекты, производство или монтаж.

Допустимые типы визуалов:

- реальные фото выполненных кухонь;
- реальные фото производства, материалов, замера, монтажа, документов;
- 3D-визуализации и AI-изображения только с явной маркировкой: "3D-визуализация", "идея планировки", "пример цветового решения";
- фото из локальных папок `E:/фото кухни 3` и `E:/фото кухни2` использовать как первичный источник, если они подходят под задачу.

Любой контент, который заявляет "реализованный проект", "производство", "монтаж", "объект в Борисове/Жодино/Минской области", должен опираться на реальные фото или подтвержденные данные.

## 2. Ожидаемый результат

После внедрения сайт должен иметь:

- установленную и проверенную Яндекс.Метрику с целями;
- усиленную главную страницу с блоками доверия, производства, документов, гарантии и портфолио;
- усиленный хаб `/locations/minskaya-oblast`;
- усиленные городские страницы Минской области;
- 20+ оформленных кейсов портфолио с фото, материалами, сроками, городом и задачей клиента;
- отдельные блоки для фото производства, монтажа, материалов и документов;
- корректную разметку schema.org;
- обновленные alt-тексты на русском языке;
- проверенный sitemap, robots, canonical, старые portfolio URL и индексацию;
- контентный план для дальнейшего роста;
- отчет приемки после внедрения.

## 4. Этап 1. Подготовка изображений

### 4.1. Обработка

Для каждого изображения:

- проверить качество, резкость, отсутствие лишних персональных данных;
- удалить или не использовать фото с личными данными, номерами документов, лицами без разрешения;
- привести к web-форматам: WebP/AVIF;
- подготовить размеры для desktop и mobile;
- сохранить исходный смысл изображения в имени файла.

### 4.2. Именование

Примеры:

```text
borisov-uglovaya-kuhnya-do-potolka-obshiy-vid.webp
zhodino-pryamaya-kuhnya-rabochaya-zona.webp
production-korpus-kuhni-sborka.webp
montage-ustanovka-verhnih-shkafov.webp
materials-mdf-fasad-obrazcy.webp
```

### 4.3. Alt-тексты

Правила:

- все alt-тексты на русском языке;
- не писать "реальный проект", если это 3D/AI;
- указывать тип кухни, город, материал или действие, если это подтверждено;
- не переспамливать ключами.

Примеры:

```text
Угловая кухня до потолка в Борисове с фасадами МДФ
Монтаж верхних шкафов кухни на объекте
Образцы фасадов МДФ и ЛДСП для кухни на заказ
3D-визуализация прямой кухни для квартиры в Минской области
```

### 4.4. Критерии приемки этапа

- Все используемые изображения имеют русские alt-тексты.
- Контентные изображения имеют стабильные размеры.
- Визуализации явно помечены как визуализации.
- Не используются изображения с персональными данными.

## 5. Этап 2. Яндекс.Метрика и цели

### 5.1. Внедрение счетчика

Задачи:

- добавить ID счетчика через переменную окружения или существующую конфигурацию проекта;
- подключить счетчик один раз на уровне root layout;
- включить Вебвизор, карту кликов и точный показатель отказов, если это разрешено настройками счетчика;
- не дублировать счетчик при переходах внутри Next.js;
- не отправлять персональные данные.

### 5.2. Цели

Обязательные цели:

- `lead_form_submit` - успешная отправка формы заявки;
- `callback_request` - успешная заявка на обратный звонок;
- `phone_click` - клик по телефону;
- `email_click` - клик по email;
- `messenger_click` - клик по Telegram/WhatsApp/Viber;
- `cta_click` - клик по важной CTA-кнопке;
- `calculator_submit` - отправка или завершение расчета;
- `quiz_complete` - если есть квиз/калькулятор с финальным шагом.

### 5.3. Проверка

После внедрения:

- открыть главную, `/locations/minskaya-oblast`, `/locations/borisov`, `/prices`;
- проверить загрузку `mc.yandex.ru`;
- проверить вызовы `ym(counterId, 'reachGoal', ...)`;
- проверить, что события форм отправляются только после успешной отправки;
- проверить отсутствие телефонов, email, имен и адресов в параметрах событий.

### 5.4. Критерии приемки этапа

- Счетчик присутствует один раз.
- Цели срабатывают на реальных действиях.
- В консоли нет ошибок Метрики.
- В события не уходит PII.

## 12. Этап 9. Schema.org и техническое SEO

### 12.1. Проверить и доработать

- `WebSite`;
- `Organization` или `LocalBusiness`;
- `BreadcrumbList`;
- `FAQPage`;
- `Service`;
- `Product`/`Offer` только там, где есть видимое основание;
- `ImageObject` при необходимости для важных изображений.

### 12.2. Правила

- Schema должна соответствовать видимому контенту страницы.
- Адрес, телефон, email, зона обслуживания должны совпадать с реальными данными.
- Не добавлять ложные рейтинги, если нет отзывов и оценок.
- Не добавлять цену как точную, если на странице указан только диапазон.

### 12.3. Технические проверки

- `robots.txt`;
- `sitemap.xml`;
- canonical;
- 200/301/404/500;
- отсутствие служебных URL в sitemap;
- старые portfolio URL;
- Open Graph;
- мобильная верстка;
- alt-тексты;
- Core Web Vitals;
- JS/CSS вес;
- lazy loading и priority для LCP-изображений.

### 12.4. Критерии приемки этапа

- Sitemap содержит только индексируемые canonical URL.
- Нет 500 на публичных SEO URL.
- Schema валидна и не конфликтует с контентом.
- Главные страницы проходят Lighthouse SEO без ошибок.

- обновление `/prices`, `/materials`, `/portfolio`;
- отправка URL на переобход.

### Месяц 2

- довести портфолио до 20+ кейсов;
- усилить P2/P3 города;
- опубликовать P1-статьи;
- собрать первые внешние размещения и отзывы.

### Месяцы 3-6

- расширять отзывы;
- добавлять реальные кейсы;
- дорабатывать страницы по данным Метрики/GSC;
- улучшать CTR title/description;
- отслеживать позиции по городам и коммерческим кластерам.

## 16. KPI

Технические KPI:

- 0 критических 500 на публичных SEO URL;
- sitemap доступен и актуален;
- все приоритетные страницы index/follow;
- Lighthouse SEO 100 для ключевых страниц;
- Метрика работает и собирает цели.

Контентные KPI:

- 20+ кейсов портфолио;
- 24 городские страницы усилены;
- 5+ статей P1 опубликованы или обновлены;
- 60+ реальных фото внедрены;
- все alt-тексты на русском.

Коммерческие KPI:

- рост кликов по телефону;
- рост заявок из форм;
- рост отправок калькулятора;
- рост CTR по региональным запросам;
- рост позиций по городским запросам Минской области.

## 17. Риски и ограничения

- Топ-1 нельзя гарантировать, потому что выдача зависит от конкурентов, истории домена, ссылок, локальных профилей и поведения пользователей.
- AI/3D-фото нельзя выдавать за реальные проекты.
- Нельзя добавлять фиктивные отзывы, рейтинги, адреса и сертификаты.
- Без реальных фото и отзывов сайт можно технически усилить, но E-E-A-T будет ограничен.
- Без Метрики и GSC нельзя корректно понять, какие страницы реально дают заявки.

## 18. Финальная приемка

Перед закрытием внедрения нужно подготовить отчет:

- что изменено в коде;
- какие страницы усилены;
- сколько фото внедрено;
- какие фото реальные, какие 3D/AI;
- какие цели Метрики настроены;
- результаты проверки sitemap/robots/canonical/schema;
- список URL, отправленных на переобход;
- оставшиеся риски;
- следующий план на 30 дней.
