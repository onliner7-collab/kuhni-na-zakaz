### noindex и redirect

Новый пример `/?sourceType=home_3d_ideas` имеет HTTP200, X-Robots-Tag `noindex, follow, noarchive`, canonical на главную. Чистая `/` имеет HTTP200, meta `index, follow`, без заголовка noindex. Это полезное разделение основной страницы и варианта выбора. Также показаны calculator?project, городские idea3d/ideaTitle/sourceType, personal-data и legacy категории/сценарии. Служебные настройки не снимать.

Аудит ответов всех 74 примеров с переходом к назначениям: 72 конечных HTTP200, два HTTP404 (шрифты). Кириллические URL проверены с percent-encoding. Это конечные статусы: исходный redirect не трактуется как 200 оригинального адреса.

Два legacy из группы 404:

- `/locations/nesvizh-Несвиж` → 301 `/locations/nesvizh`;
- `/+375293720674` → 301 `/contacts`.

Шрифты `/_next/static/media/21350d82a1f187e9-s.p.woff2` и `e4af272ccee01ff0-s.p.woff2` отмечены Google по сканированию июля. Их не перенаправляем на HTML страницы и не создаём фиктивные font-файлы. Проверку исправления всей группы 404 не запускаем: два намеренно отсутствующих ресурса сохраняют этот статус.

### Изображения — найденная техническая ошибка

В robots.txt уже есть более специфичное `Allow: /kapi/watermarked-image` перед общим `Disallow: /kapi/`. Два изображения из отчёта возвращают 200 image/webp. Сам route handler успешно сгенерированного изображения задаёт `X-Robots-Tag: index`, но общий middleware добавлял `noindex, nofollow, noarchive` ко всему /kapi, перекрывая явную политику изображения.

Это блокирует индексирование самого изображения, а не HTML страницы статьи. [Спецификация Google](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag) подтверждает применение noindex к не-HTML ресурсам и преимущество более строгой директивы.

Исправление: пять строк в `withPublicNoindexHeader` — точное исключение pathname `/kapi/watermarked-image` перед общей политикой API/параметров. Никакие API/админка/поиск/thanks/дубли не открываются. Error responses остаются 400/404, обработчик и защита чтения публичных файлов не меняются.

Тесты 3/3 проверяют настоящий middleware: изображение не получает общий noindex; `/kapi/leads`, `/api/test`, `/admin/login`, вложенный `/kapi/watermarked-image/private` остаются noindex; обычная категория открыта, параметризованная главная закрыта. HTTP smoke локально: изображение 200/index/image/webp, query-главная 200/noindex. Типизация PASS после исправления совместимости собственной smoke-regex с ES2017 (`[\s\S]` вместо флага dotAll). Изменён только тест, runtime маленьких кухонь сохранён.

Пользователь отдельно разрешил узкий деплой этого исправления. База сервера `a00783c2e8c637497cb2a2079b0024a94d83515d`, релиз `09e3d4ac9e891d13128212f922697ae11235f49c`, ветка `codex/image-indexing-release`. Runtime diff только middleware; ещё два тестовых файла. Dirty workspace не публикуется.

Публикация завершена: BUILD_ID `xyx2r3V8m3BOyRye2mt8c`; server build/lint/type validation PASS, 173/173 маршрута с рабочей БД; unit 3/3 PASS на сервере. Конфигурация сборки временно cpus=1, webpackMemoryOptimizations, heap 1400 МБ и дополнительные 2 ГБ swap; config/tsconfig восстановлены, временный swap выключен/удалён, постоянный swap сохранён, service active и tracked worktree чистый. При переключении один 502 в smoke сменился 200; скрипт активации подтвердил индексируемый image response.

Production HTTP: оба точных image URL из Google — 200/image-webp/X-Robots-Tag index. Query-главная, admin/login, thanks и kapi/leads сохраняют noindex. После shared-правки повторены все 112 URL: 112/112 HTTP200/indexable/self-canonical. Сравнение с baseline всех 112: title/H1/canonical/meta robots/X-Robots совпали, изменений 0. Это включает пять защищённых страниц и Борисов. Production Playwright 8/8 PASS, форма только с перехватом, реальные заявки не отправлялись. Evidence: `production-policies.json`, `sitemap-before.json`, `sitemap-crawl.json`, `metadata-comparison.json`, `production-tests/`.
