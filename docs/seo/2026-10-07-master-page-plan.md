| как сэкономить на кухне; как распределить бюджет | статьи и пояснения бюджетной страницы, не копия /prices |
| кухня + стиль | соответствующая /styles/... |
| кухня из МДФ/ЛДСП/шпона и т. п. | соответствующая /materials/...; покупку отдельных фасадов не обещать без такой услуги |
| как выбрать; сравнение; размеры; ошибки | одна отвечающая этому вопросу /blog/... |
| конкретный реализованный проект | конкретная /portfolio/... только при доказуемом происхождении |

Это редакционное назначение, не запрет поисковику показывать другую релевантную страницу. Тип + город не размножаем в сотни посадочных. На категории допустима правдивая зона обслуживания со ссылкой на город; в городе — краткий блок категории с обратной ссылкой. Не требуется вычищать географию из адресов и контактов.

Не назначать изготовлению на заказ чужие бренды, б/у, Куфар, рестораны, кухонные столы/диваны, отдельную бытовую технику. «Готовая» и «модульная» кухня допустимы в честном сравнении, а не как обещание продаваемого ассортимента.

## 3. Общий контракт для каждого нового чата

1. Прочитать AGENTS/AGENT и актуальный код. Зафиксировать git diff и не перезаписывать пользовательские изменения, особенно Борисов. Этот документ разрешает подготовку плана, а не автоматический деплой всех страниц.
2. Снять baseline одного URL: HTTP, HTML, title/description/H1/canonical, robots, видимые блоки, schema, формы, изображения. В SEO-панелях работать браузером, авторизацию выполняет пользователь.
3. Проверить 5–10 начальных коммерческих фраз и смысловые расширения в Wordstat: регион Беларусь/нужный город, дата, широкая и уточнённая частотность, операторы. Числа помечать источником, нулевые и неподтверждённые сочетания не маскировать.
4. Посмотреть Google и Яндекс вручную/разрешёнными инструментами по 3–5 представительным фразам, указать регион, устройство и дату. Сопоставить 5 релевантных конкурентов: тип страницы, предложение, цены, примеры, локальные условия, доверие, UX. Это исследование, а не автоматический скрейпинг поисковиков.
5. Выбрать 1 основной кластер, 3–8 поддерживающих подкластеров. Проверить соседние URL. Для каждого кластера указать владельца, исключённые намерения, доступные факты. Число запросов в тексте и «плотность» не нормировать.
6. В title и H1 поставить основной смысл; не превращать их в списки ключей. Description отражает страницу и следующий шаг. Подобрать рабочий вариант и 2 альтернативы, выбрать по соответствию намерению, а не выдуманной прибавке CTR. Длина 50–65/140–170 символов — редакционный ориентир, не требование и не гарантия сниппета.
7. Сверстать mobile-first: фото первого экрана, короткое вступление, визуальные карточки, примеры комплектаций, вопросы и форма. Подробности — доступные аккордеоны/таблицы, но не скрытый SEO-текст. Убирать повторные пояснения между блоками. Не копировать Борисов заменой города.
8. Реальные цены показывать в BYN с датой/составом/исключениями. Если цены неизвестны, явно описать способ расчёта; не обещать «каталог с ценами», пока их нет. Не выдавать AI-изображения за завершённые объекты/отзывы. Служебное «визуализация» на каждой карточке не обязательно: разделить примеры дизайна и доказанные работы по назначению.
9. Ссылки: хлебные крошки, родитель, соответствующая категория/город, цена/расчёт, полезная статья или подтверждённый кейс. Не навешивать все города и ключи на каждый блок. Нет обязательной квоты exact-match анкоров.
10. Сохранить существующий URL и self-canonical для самостоятельной страницы. Любые 301, noindex, изменение canonical или объединение URL — отдельное решение после анализа трафика/ссылок/индексации. lastmod обновлять только реально изменённой странице.
11. Schema по видимым фактам: BreadcrumbList; Organization/LocalBusiness только с реальными данными бизнеса; Article для статьи; Product/Offer только для подходящего продукта с подтверждёнными данными. Не выдумывать рейтинги/филиалы. FAQ не обещает расширенный сниппет.
12. Проверка: типизация, релевантные тесты, production build; 320/390/768/1440; один ясный H1; нет overflow, битых изображений, плохих якорей, JS ошибок; WebP и naturalWidth>0; водяные обложки /kapi/watermarked-image дают 200, если используются. Тест заявки перехватывается и не создаёт реальный лид. Проверить sourcePage, город и выбранные параметры.
13. Если запрос включает деплой — выпуск только своего diff после проверки актуального серверного HEAD, без старых чужих локальных изменений. После публикации повторить production QA, сохранить возможность отката. Новые kitchen images только через imagegen, исходник + WebP в проекте.
14. Передать отчёт в docs/seo/YYYY-MM-DD-{slug}.md: baseline, запросы с источниками, принятые title/description/H1, блоки, ссылки, изменённые файлы, тесты, статус деплоя. URL отправлен на переобход ≠ URL проиндексирован.

## 13. Что нужно для цели топ-5 кроме изменения текста

1. Индексация и правильный выбранный canonical по данным панелей, отсутствие технических блокеров.
2. Содержательное предложение: реальные комплектации, честный расчёт, фотографии/кейсы, полезные отличия страницы.
3. Подтверждённые контакты, юридические данные, реальные отзывы; карточки организации с фактической географией. Не создавать фиктивные филиалы ради регионов.
4. Естественное узнавание компании и упоминания партнёрами/клиентами. Не покупать спам-ссылки, не накручивать поведение/отзывы.
5. Быстрый мобильный интерфейс, удобная заявка, функциональные инструменты, понятные условия заказа.
6. Проверка результата по URL, запросу, поисковику, региону и устройству; топ-5 органики отличать от рекламных мест/карт.

## 15. Основания и передача

Использованы keyword-research (кластеризация без выдуманных метрик), meta-tags-optimizer (рабочие варианты сниппетов, без обещанных процентов CTR), internal-linking-optimizer (смысловые связи), serp (обязательное текущее исследование в каждом чате), seo-search-readiness/technical-seo-developer (индексация, фактическая schema, проверка релиза).

Это новый мастер-план, не доказательство проведённого аудита всех 112 страниц или текущих позиций. Нужны свежие выгрузки запрос→URL из Search Console и Яндекс Вебмастера, Wordstat по очередным кластерам, подтверждённые цены/условия/кейсы. Следующий шаг — новый чат для / либо подготовительный технический аудит, если URL не индексируются.
